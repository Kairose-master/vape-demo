# TXT 가져오기 후 응답성 수정

FilePipeline은 별도 샌드박스 프로세스로 파일 선택과 등록소를 담당합니다.
이전에는 `runModal()`을 마친 뒤 메인 스레드가 다음 `readLine()`에서 대기했고,
기본 AppKit 이벤트 루프가 없어 활성 보조 앱이 응답하지 않을 수 있었습니다.

이제 `NSApp.run()`을 유지하고 전용 직렬 큐에서 stdin을 기다립니다.
각 요청은 메인 큐에 동기 전달하므로 UI 및 등록소 변경은 메인 스레드에서
순서대로 실행됩니다. 모달의 중첩 이벤트 루프 동안 다음 요청이 들어와
진행 중인 등급/승인 상태를 바꾸지 않도록 입력 측에도 역압력을 적용합니다.
응답을 flush한 후 다음 입력을 읽으며 EOF/단일 요청 종료도 AppKit에서 처리합니다.

파일 선택 및 리비전 작성/비교 창은 성공·취소·오류 모두 정리합니다.
보조 앱이 여전히 활성 상태이고 처음의 전면 앱이 VAPE 콘솔일 때만
그 콘솔로 활성화를 돌려줍니다. 사용자가 다른 앱으로 이동했다면 복귀하지 않습니다.
파일 스코프, 샌드박스 권한, 정책 v2, 승인 토큰 및 Keychain 동작은 변경하지 않습니다.

## 재현 검사

```sh
./Start\ VAPE.command --ui-test
./Start\ VAPE.command --self-test
```

첫 명령은 새 QA 번들과 격리 등록소를 사용합니다. 기존 파일/키는 사용하지 않습니다.
`check_file_bridge.py`는 실제 helper 실행 파일에서 stdin 대기 중 AppKit heartbeat,
메인 스레드 처리, 연속 합성 가져오기·저장·조회, 잘못된 JSON/크기 초과 후 복구,
역할 제한, 단일 요청 종료 및 EOF 종료를 검사합니다.
`--bridge-self-test`는 격리 합성 저장소와 주입된 파일 선택기만 사용하는 진단 모드입니다.
정상 GUI 브리지의 프로토콜에는 heartbeat 명령을 추가하지 않습니다.
기존 helper 자체 검사는 L2 쓰기 차단, L3 저장/취소/승인 재사용 차단과 원본 보존을 검사합니다.

## 수동 GUI 확인

화면 제어가 가능한 Mac에서 `./Start\ VAPE.command --gui-qa`로 실행하고
합성 TXT만 사용해 연속 가져오기, 선택 취소, L3 편집 취소, 비교 후 취소 및
별도 승인 저장을 확인합니다. 각 종료 후 콘솔 반응성과 복귀를 확인하고,
모달 표시 중 다른 앱으로 이동한 경우 자동으로 포커스를 빼앗지 않는지도 확인합니다.

이번 수정 검증 시 원격 화면 제어가 `timeoutReached (-10005)`로 실패했습니다.
따라서 실제 클릭과 포커스 전환은 미검증이며, 자동 검사 통과로 이를 대신 주장하지 않습니다.
EOF는 대기 중/완료 후 검증합니다. 모달 진행 중 EOF는 사용자가 모달을 닫은 뒤 처리됩니다.
